Why Pin Context?

  • Open tabs do not form named task contexts
  • File sets must be rebuilt manually
  • No dedicated context timeline
  • No built-in JSON transfer for Pin Context sets
  • No Pin Context-specific Explorer actions
  • No Pin Context metadata tools for MCP agents
  • No context-change approval flow for this feature
  • No named context restore workflow
  • Named contexts for tasks and workflows
  • Pin or unpin files directly in Explorer
  • Restore task-specific file sets
  • Context history and fast switching
  • Portable, validated JSON import and export
  • Keyboard shortcuts and Quick Picks
  • MCP and public API for compatible AI agents
  • Explicit approval before context changes

CLAUDE CODE · STDIO

Connect Claude Code to the active VS Code workspace

  1. Open the target project in VS Code, wait for Pin Context to activate, then run “Pin Context: Copy MCP Client Configuration”.
  2. Copy the mcpServers.pin-context object from the generated JSON, without the outer mcpServers object.
  3. Run the command below in a terminal, replacing the placeholder with the exact JSON object from the generated configuration:
    claude mcp add-json pin-context '<copied pin-context JSON object>' --scope user
  4. Run claude mcp list, then use /mcp inside Claude Code to confirm that the server is connected.
Official Claude Code MCP guide↗

Workspace and session requirements

The generated bridge configuration is tied to the current VS Code extension session. Keep that workspace open. If the connection stops working after VS Code reloads, copy the configuration again and update the Claude Code server entry.

Verify the connection with /mcp in Claude Code.
OPENAI CODEX · CONFIG.TOML

Connect Pin Context to Codex CLI or its IDE extension

  1. Open the target project in VS Code, wait for Pin Context to activate, and run “Pin Context: Copy MCP Client Configuration”.
  2. Open ~/.codex/config.toml and add the server table below. Copy the exact command, args, and PIN_CONTEXT_VERSION values from the generated JSON. 
    [mcp_servers.pin-context]
command = "node"
args = [
  "/ABSOLUTE/PATH/TO/out/mcp-server.js",
  "--bridge-config",
  "/ABSOLUTE/PATH/TO/BRIDGE_CONFIG"
]
env = { PIN_CONTEXT_VERSION = "COPY_VERSION_VALUE" }
  3. Replace each placeholder with the corresponding value from the generated configuration. Keep the argument order unchanged.
  4. Run codex mcp list. In the Codex TUI, you can also run /mcp to inspect the connection.
Official Codex MCP guide↗

Workspace and session requirements

Codex CLI and its IDE extension use the same user-level MCP configuration. Keep the VS Code workspace connected to Pin Context open. If Node.js is not on the client’s PATH, set command to its absolute path: use which node on macOS/Linux or where node on Windows.

Verify that codex mcp list includes pin-context.
BUILT-IN MCP PROVIDER

Use Pin Context tools in VS Code Chat

  1. Open VS Code Chat, then open the tool picker.
  2. Find Pin Context and enable its tools for the current chat.
  3. Try the read-only test prompt below. VS Code shows its own confirmation dialog for MCP tools that change state.

Permissions

Read-only operations do not change extension state. VS Code asks for approval before running an MCP tool that changes state; review the requested action before approving it.

STDIO · LOCAL PROCESS

Connect another MCP-compatible client

  1. Ensure Pin Context is active in the VS Code workspace you want to expose.
  2. Run “Pin Context: Copy MCP Client Configuration”, then copy the mcpServers.pin-context object from the generated JSON.
  3. Add the entry to the client’s stdio MCP configuration. Keep the command, argument order, and environment variables unchanged.
  4. Restart the client or reconnect to the MCP server, then confirm that the Pin Context tools appear in the tool list.
Koda MCP setup guide↗

Local connection

The client starts a local Node.js process that forwards requests to the active extension. Node.js must be available to the client; set its absolute path if needed. Do not share the generated bridge configuration with others because it contains access credentials.

FIRST CONNECTION CHECK

Test tool discovery without making changes

Use the Pin Context MCP tools to report the active context, list available contexts, and list pinned files. Do not switch contexts or change any pins.

ⓘPin Context returns context metadata and file paths, not file contents. The agent reads file contents through its own workspace tools. Changes to contexts or pinned files require approval.

A workflow that stays out of your way

  1. Pin task-related files from the editor or the Explorer context menu.
  2. Save the pinned set as a named context for the task.
  3. Switch contexts as you move between features or Git branches.
  4. Export context sets to JSON to move them between workspaces or share them with your team.
  5. Use Quick Open and the context timeline to return to recent work.
